## 이 보고서를 읽기 전에

이 보고서는 **DNN(Deep Neural Network) 모델의 실행 시간을 미리 예측하는 시스템**을 만드는 과정을 기록합니다.

쉽게 말하면:
> "새로운 AI 모델을 만들었을 때, 실제로 돌려보기 전에 '이 모델은 CPU에서 약 50ms 걸릴 것 같다'고 미리 예측하는 프로그램을 개발하는 것입니다."

## 1. 3단계 목적

### 1.1 무엇을 하려는가?

1-2단계에서는 다양한 AI 모델(ANN, CNN)을 실제로 실행해서 시간을 측정했습니다.  
3단계에서는 그 측정 데이터를 **기계학습(Machine Learning)** 으로 학습시켜,  
앞으로 새 모델이 들어왔을 때 실행 시간을 자동으로 예측하는 **예측 모델**을 만듭니다.

```
[기존 방식]  새 모델 → 직접 실행 → 시간 측정  (오래 걸림)

[예측 방식]  새 모델의 구조 정보 → 예측 모델 → 예상 실행 시간 출력  (즉시)
```

### 1.2 사용한 알고리즘 — Random Forest와 XGBoost

이 두 알고리즘은 모두 **회귀(Regression)** 문제에 사용됩니다.  
회귀란 "숫자를 예측하는 것" 입니다. (예: 집값 예측, 온도 예측, 실행 시간 예측)

**Random Forest (랜덤 포레스트) — 쉬운 비유:**
> 친구 100명에게 "이 모델 실행 시간이 몇 ms일 것 같아?"라고 물어보고,  
> 100명의 답을 평균 낸다. 한 명의 판단보다 100명의 평균이 훨씬 정확하다.

- 실제로는 '결정 트리(Decision Tree)'라는 판단 구조를 100개 만들어 평균
- 과적합(데이터를 너무 외워버리는 현상)에 강함
- 어떤 정보가 예측에 중요한지 'Feature 중요도'로 확인 가능

**XGBoost — 쉬운 비유:**
> 첫 번째 친구가 틀린 부분을 두 번째 친구가 보완하고,  
> 두 번째 친구가 틀린 부분을 세 번째 친구가 보완한다.  
> 이렇게 100번 반복하면 점점 정확해진다.

- 이전 단계의 '오차'를 다음 단계가 줄여나가는 방식 (Gradient Boosting)
- 일반적으로 Random Forest보다 높은 정확도
- 하이퍼파라미터(학습률, 깊이 등) 튜닝이 중요

### 1.3 예측 대상

| 예측 대상 | 단위 | 설명 |
|-----------|------|------|
| `inference_time_mean_ms` | 밀리초(ms) | 모델이 이미지 1배치를 분류하는 데 걸리는 시간 |
| `training_time_mean_sec` | 초(sec) | 모델이 1 epoch(전체 데이터 1회 학습) 걸리는 시간 |

### 3.2 v1 — 첫 번째 시도 (50개 데이터, 기본 방식)

**방법:**
- 50개 데이터를 Train(40개) / Test(10개)로 나눔
- 기본 파라미터로 Random Forest, XGBoost 학습
- 시간 값을 그대로 학습 (변환 없음)

**결과:**

| 모델 | 타겟 | R² 점수 |
|------|------|---------|
| Random Forest | 추론 시간 | 0.4176 |
| XGBoost | 추론 시간 | -0.0381 ← 음수! |
| Random Forest | 학습 시간 | -0.0286 ← 음수! |
| XGBoost | 학습 시간 | -0.0905 ← 음수! |

> **R² 점수 해석 방법:**
> - R² = 1.0 : 완벽한 예측 (실제값 = 예측값)
> - R² = 0.0 : 예측 모델이 평균값만 출력하는 것과 같음 (쓸모없음)
> - R² < 0.0 : 평균값보다도 못한 예측 (매우 나쁨)
>
> 추론 시간은 0.4 정도로 나쁘진 않지만, 학습 시간은 음수가 나와 개선이 필요합니다.

**왜 이렇게 낮은가? — 핵심 문제: 시간 값의 범위가 너무 넓음**

```
추론 시간: 가장 작은 값 0.03ms, 가장 큰 값 799ms  (약 26,000배 차이)
학습 시간: 가장 작은 값 3.8초,  가장 큰 값 6332초 (약 1,600배 차이)
```

> 비유: 학생 성적을 예측하는데, 한 학생은 1점, 다른 학생은 26,000점인 상황.  
> 모델이 큰 값(26,000점)에만 집중하고 작은 값(1점)은 무시하게 됩니다.

### 3.3 v2 — 개선판 (74개 데이터, 3가지 핵심 개선)

#### 개선 1: 로그 변환 (Log Transform)

**왜 필요한가?**  
시간 값의 범위(0.03 ~ 799ms)가 너무 넓어서, 큰 값에만 끌려다니는 현상 발생.  
로그를 씌우면 값의 범위가 균일해져서 모델이 골고루 학습할 수 있습니다.

```
log1p(x) = log(1 + x)   ← x=0일 때도 안전하게 사용 가능

변환 전:  0.026ms ~ 799ms   (30,000배 차이)
변환 후:  0.025  ~ 6.685    (270배 차이 — 훨씬 관리하기 쉬운 범위)
```

> 비유: 집값을 예측할 때, "1억, 2억, 100억"을 그대로 쓰면  
> 100억짜리에만 집중하지만, 로그를 쓰면 "8, 8.3, 11"로 균일해집니다.

학습은 로그 변환된 값으로 하고, 예측 후에는 `expm1()`으로 원래 단위로 되돌립니다.

#### 개선 2: K-Fold 교차검증 (K=5)

**왜 필요한가?**  
74개 데이터를 단 한 번 Train(60)/Test(14)로 나누면, 운에 따라 결과가 크게 달라집니다.  
K-Fold는 데이터를 5등분해서 5번 반복 평가하고 평균을 냅니다.

```
1회차: [1/5 테스트] [2/5+3/5+4/5+5/5 학습]
2회차: [2/5 테스트] [1/5+3/5+4/5+5/5 학습]
3회차: [3/5 테스트] [1/5+2/5+4/5+5/5 학습]
4회차: [4/5 테스트] [1/5+2/5+3/5+5/5 학습]
5회차: [5/5 테스트] [1/5+2/5+3/5+4/5 학습]
→ 5번 점수의 평균 = 최종 성능
```

> 비유: 시험을 한 번만 보면 운이 나쁜 날엔 결과가 나쁘지만,  
> 5번 보고 평균을 내면 실력을 더 정확히 알 수 있습니다.

#### 개선 3: GridSearchCV — 하이퍼파라미터 자동 튜닝

**하이퍼파라미터란?**  
학습 전에 사람이 직접 설정하는 값들. 예: 결정 트리를 몇 개 만들지, 트리를 얼마나 깊게 할지.

GridSearchCV는 가능한 모든 조합을 자동으로 시도해서 가장 좋은 설정을 찾아줍니다.

```
Random Forest 탐색 조합:
  트리 개수(n_estimators): 50, 100, 200  →  3가지
  최대 깊이(max_depth): 없음, 5, 10, 20  →  4가지
  최소 분할 샘플(min_samples_split): 2, 5, 10  →  3가지
  최소 리프 샘플(min_samples_leaf): 1, 2, 4  →  3가지
  총 3×4×3×3 = 108가지 조합 중 최적 선택
```

## 4. 최종 성능 결과 (v2 개선판)

### 4.1 성능 지표 해석 방법

| 지표 | 의미 | 좋은 방향 |
|------|------|----------|
| **RMSE** (Root Mean Square Error) | 예측 오차의 평균. 단위는 예측 대상과 같음 (ms, 초) | 작을수록 좋음 |
| **MAE** (Mean Absolute Error) | 예측 오차의 절댓값 평균. RMSE보다 이상치에 덜 민감 | 작을수록 좋음 |
| **R²** (결정계수) | 예측 모델이 데이터를 얼마나 잘 설명하는가 (0~1) | 1에 가까울수록 좋음 |
| **R²_log** | log 공간에서의 R² (모델이 패턴을 잘 배웠는지 참고용) | 1에 가까울수록 좋음 |
| **CV R²** | K-Fold 교차검증으로 측정한 평균 R² (가장 신뢰할 수 있는 지표) | 1에 가까울수록 좋음 |

### 4.2 최종 성능표

| 모델 | 타겟 | RMSE | MAE | R² | R²_log | CV R² |
|------|------|------|-----|-----|--------|-------|
| Random Forest | 추론 시간(ms) | 96.86ms | 18.43ms | 0.2087 | 0.8855 | 0.8714 |
| **XGBoost** | **추론 시간(ms)** | **55.17ms** | **10.64ms** | **0.7432** | **0.9466** | **0.9426** |
| Random Forest | 학습 시간(sec) | 735.84초 | 105.76초 | 0.0127 | 0.7872 | 0.7940 |
| XGBoost | 학습 시간(sec) | 734.16초 | 101.99초 | 0.0173 | 0.7786 | 0.8335 |

### 4.3 결과 해석 — "이 숫자가 무슨 의미인가?"

**추론 시간 예측 — 성공적!**

XGBoost의 R² = **0.7432** (원래 단위)

> 100ms가 걸리는 모델이 있을 때,  
> 예측 모델은 평균적으로 ±55ms 오차 범위 내로 예측합니다.  
> R² = 0.74는 "데이터 분산의 74%를 모델이 설명할 수 있다"는 의미로,  
> 74개 데이터로는 상당히 좋은 성능입니다.

log 공간 R² = **0.9466** → 모델이 패턴을 매우 잘 학습했음을 의미

**학습 시간 예측 — 아직 낮음 (이유가 있음)**

학습 시간 R² ≈ 0.01 (원래 단위)

> 이것은 코드 문제가 아니라 **데이터 문제**입니다.  
> MobileNetV2 CPU 학습 시간이 **6332초**인데, 이는 다른 값(평균 수백 초)에 비해 너무 극단적입니다.  
> 이 하나의 값이 예측 전체를 어렵게 만들고 있습니다.  
> 4단계에서 Transformer, GAN 데이터가 추가되면 자연스럽게 개선됩니다.

log 공간 R² ≈ **0.78~0.83** → log 변환 후에는 패턴 학습이 잘 됨

### 4.4 v1 → v2 개선 효과 요약

| 모델 | 타겟 | v1 R² | v2 R² | 변화 |
|------|------|-------|-------|------|
| XGBoost | 추론 시간 | -0.04 | **+0.74** | **+0.78 대폭 개선** |
| RF | 추론 시간 | +0.42 | +0.21 | K-Fold로 더 엄격하게 평가 |
| XGBoost | 학습 시간 | -0.09 | +0.02 | 소폭 개선 |
| RF | 학습 시간 | -0.03 | +0.01 | 소폭 개선 |

> RF 추론 시간이 줄어보이는 이유:  
> v1은 운 좋게 쉬운 10개 테스트를 골랐고, v2는 K-Fold로 더 엄격하게 평가했기 때문입니다.

## 7. 한계점과 다음 단계

### 7.1 현재 한계

**1) 학습 시간 예측 정확도가 낮음**
- MobileNetV2 CPU 학습 6332초가 극단적 이상치(outlier)
- ANN(2~70초)과 CNN(수백~수천 초)의 스케일 차이가 근본적으로 큼
- → 4단계에서 Transformer/GAN 데이터 추가 시 자연스럽게 개선 예상

**2) 모델 유형이 2가지뿐 (ANN, CNN)**
- 예측 모델이 ANN/CNN 패턴만 학습함
- Transformer, GAN처럼 전혀 다른 구조가 들어오면 예측 정확도 보장 어려움

**3) 단일 하드웨어 (M1 Mac)**
- CPU와 MPS(Apple Silicon GPU)만 측정
- NVIDIA CUDA GPU 환경 데이터 없음

### 7.2 4단계 계획

```
목표: Transformer, GAN 모델의 실행 시간 측정 (학교 연구실 GPU)

측정 모델:
  - 소형 Transformer (직접 구현: 임베딩 + Multi-Head Attention + MLP)
  - 소형 GAN (Generator + Discriminator, CIFAR-10 기반)

기대 효과:
  - 데이터 다양성 증가 → 예측 모델 일반화 성능 향상
  - 학습 시간 예측 R² 개선
  - CUDA GPU Feature 활용 가능
```

### 7.3 최종 목표 (5단계)

```
입력: ONNX 형식의 AI 모델 파일
  ↓
모델 구조 자동 분석 (레이어, 파라미터, 연산량 추출)
  ↓
Feature 벡터 자동 생성
  ↓
예측 모델 적용
  ↓
출력: CPU/GPU에서의 추론·학습 시간 예측값
```

## 8. 결론

3단계에서는 **"모델 구조 정보만으로 실행 시간을 예측할 수 있다"는 가능성을 수치로 검증**했습니다.

핵심 성과:
- XGBoost 추론 시간 R²: -0.04 → **0.74** (원래 단위)
- XGBoost 추론 시간 R²: **0.95** (log 공간, 학습 품질 기준)
- 데이터 74개, Feature 29개 기반 예측 파이프라인 완성

3가지 핵심 개선 기법(로그 변환, K-Fold, GridSearchCV)을 통해  
적은 데이터로도 의미 있는 예측이 가능함을 확인했습니다.  
4단계에서 더 다양한 모델 데이터를 추가하면 예측 성능이 더욱 향상될 것입니다.

### C. 용어 정리

| 용어 | 설명 |
|------|------|
| ANN | Artificial Neural Network. 완전연결 신경망. 가장 기본적인 딥러닝 구조 |
| CNN | Convolutional Neural Network. 이미지 처리에 특화된 신경망 |
| Feature | 예측 모델의 입력으로 사용하는 수치화된 정보 |
| Epoch | 전체 학습 데이터를 한 번 다 돌리는 단위 |
| Warmup | 측정 전 몇 번 실행하여 캐시/GPU 초기화를 마치는 과정 |
| R² | 예측 정확도 지표. 1에 가까울수록 좋음, 0 미만이면 매우 나쁨 |
| RMSE | 예측 오차의 크기. 작을수록 정확한 예측 |
| 로그 변환 | 매우 넓은 범위의 숫자를 균일하게 압축하는 수학 기법 |
| K-Fold | 데이터를 K등분해서 K번 반복 평가하여 평균 성능을 구하는 방법 |
| GridSearchCV | 가능한 모든 하이퍼파라미터 조합을 시도하여 최적값을 자동으로 찾는 방법 |
| 과적합 | 학습 데이터를 너무 외워버려 새 데이터 예측이 나빠지는 현상 |
