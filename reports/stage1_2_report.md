## 1. 프로젝트 개요

### 1.1 연구 목적
AI 프로세서 SW 프레임워크 연구의 일환으로, DNN 모델의 추론 및 학습 시간을 모델 구조만으로 사전 예측할 수 있는 시스템 개발

### 1.2 연구 범위
- 다양한 DNN 모델(ANN, CNN, Transformer, GAN)의 실행 시간 측정
- 모델 구조 정보를 기반으로 한 시간 예측 모델 개발
- 하드웨어별(CPU, GPU) 성능 차이 분석

## 2. 1단계: 환경 설정 및 기본 데이터 수집

### 2.1 완료 작업

#### 2.1.1 개발 환경
- **하드웨어:** M1 MacBook (CPU, MPS)
- **소프트웨어:** Python 3.13, PyTorch, PyCharm
- **데이터셋:** MNIST (손글씨 숫자 인식)

#### 2.1.2 구현 내용
1. **시간 측정 프레임워크 개발** (`utils/timer.py`)
   - Warmup 실행으로 초기화 오버헤드 제거
   - 다중 반복 측정 및 통계 처리
   - CPU/MPS 하드웨어 동기화 지원

2. **단순 ANN 모델 구현** (`models/ann_models.py`)
   - 레이어 수: 2, 3, 4층
   - Width: 64, 128, 256, 512
   - 총 14개 모델 구성

3. **실험 자동화** (`experiments/ann_mnist_experiment.py`)
   - 모델 학습 및 시간 측정 자동화
   - 결과 데이터 CSV 저장

### 2.2 실험 결과

#### 2.2.1 데이터 수집
- **총 데이터 포인트:** 28개 (14 모델 × 2 디바이스)
- **측정 항목:**
  - 추론 시간 (ms)
  - 학습 시간 (초/epoch)
  - 모델 파라미터 수
  - 모델 구조 정보

#### 2.2.2 주요 발견 사항

**1) 파라미터 수와 실행 시간의 상관관계**
- CPU: 파라미터 증가 → 추론 시간 증가 (강한 양의 상관관계)
- MPS: 동일한 경향성 유지

**2) CPU vs MPS 성능 비교**
```
평균 추론 시간:
- CPU: 0.08 ms
- MPS: 0.60 ms

평균 학습 시간:
- CPU: 3.1 초
- MPS: 5.4 초
```

**3) 작은 모델에서의 GPU 오버헤드**
- 파라미터가 적은 모델(~100K)에서는 MPS가 CPU보다 느림
- GPU 초기화 및 데이터 전송 오버헤드가 연산 시간보다 큼
- 파라미터가 증가할수록 MPS 효율성 증가

## 3. 2단계: CNN 모델로 데이터 확장

### 3.1 완료 작업

#### 3.1.1 개발 환경
- **데이터셋:** CIFAR-10 (컬러 이미지 분류)
- **모델 종류:**
  - SimpleCNN (자체 구현)
  - ResNet18 (표준 아키텍처)
  - MobileNetV2 (경량 아키텍처)

#### 3.1.2 구현 내용
1. **CNN 모델 구현** (`models/cnn_models.py`)
   - SimpleCNN: 레이어 수(2,3,4) × 채널 수(16,32,64) = 9개
   - ResNet18: CIFAR-10용으로 수정
   - MobileNetV2: CIFAR-10용으로 수정

2. **CIFAR-10 실험** (`experiments/cnn_cifar10_experiment.py`)
   - 총 11개 모델 측정
   - 학습 정확도 함께 기록

### 3.2 실험 결과

#### 3.2.1 데이터 수집
- **총 데이터 포인트:** 22개 (11 모델 × 2 디바이스)
- **파라미터 범위:** 365K ~ 11.1M

#### 3.2.2 주요 발견 사항

**1) SimpleCNN 성능 분석**
```
레이어별 정확도:
- L2 (2층): 39-49%
- L3 (3층): 53-56%
- L4 (4층): 58-61%

→ 레이어 증가 시 정확도 향상
→ 채널 수 증가는 소폭 영향
```

**2) CPU vs MPS 성능 비교**
```
SimpleCNN:
- 작은 모델: MPS 2-3배 빠름
- 중간 모델: MPS 2-5배 빠름

ResNet18:
- CPU: 799 ms
- MPS: 80 ms
- 약 10배 가속

MobileNetV2:
- CPU: 508 ms
- MPS: 16 ms
- 약 31배 가속 (최고 효율)
```

**3) 모델 아키텍처별 특성**

| 모델 | 파라미터 | CPU 추론 | MPS 추론 | 특징 |
|------|----------|----------|----------|------|
| SimpleCNN_L2_C16 | 1.05M | 6.1ms | 2.0ms | 가장 단순 |
| SimpleCNN_L4_C64 | 2.60M | 95.8ms | 9.9ms | 깊고 넓음 |
| ResNet18 | 11.1M | 799ms | 80ms | 잔차 연결 |
| MobileNetV2 | 2.23M | 508ms | 16ms | 경량화 설계 |

**4) 주요 인사이트**
- MobileNetV2: 파라미터는 적지만 CPU에서 ResNet18보다 느림
  - Depthwise Convolution의 CPU 비효율성
- MPS에서는 MobileNetV2가 가장 빠름
  - 병렬 처리에 최적화된 구조
- 복잡한 모델일수록 GPU 가속 효과 큼

## 4. 1-2단계 통합 분석

### 4.1 데이터 통합
- **ANN (1단계):** 14 모델 × 2 디바이스 = 28 포인트
- **CNN (2단계):** 11 모델 × 2 디바이스 = 22 포인트
- **총합:** 50 데이터 포인트

### 4.2 주요 발견

#### 4.2.1 모델 복잡도와 성능
1. **파라미터 수가 증가하면 실행 시간도 증가**
   - 강한 양의 상관관계 (로그 스케일에서도 명확)
   - CPU와 MPS 모두 동일한 경향

2. **레이어 깊이의 영향**
   - SimpleCNN에서 레이어 증가 → CPU 시간 기하급수적 증가
   - MPS에서는 상대적으로 완만한 증가

#### 4.2.2 하드웨어별 특성

**CPU 특성:**
- 단순한 연산에 효율적
- 작은 모델(<1M 파라미터)에서 경쟁력
- 복잡한 모델에서는 급격한 성능 저하

**MPS (M1 GPU) 특성:**
- 초기화 오버헤드 존재
- 파라미터 >1M부터 효율성 발휘
- 병렬화 가능한 연산에서 최대 31배 가속

- 예측 정확도 평가

- ViT-tiny (Vision Transformer) 측정

**학교 연구실 필요 이유:**
- 대형 모델 학습에 고성능 GPU 필수
- CUDA 지원 GPU 환경 필요
- 장시간 실험 가능한 안정적 환경

### 5.3 5단계: 검증 및 문서화
- 전체 예측 모델 정확도 평가
