# 앙상블 예측기 설계 — 단일 XGBoost를 구간 게이트 앙상블로 바꾸는 과정

작성 2026-09-18. 브랜치 `ensemble` (`racs-cr` 92e0cb0에서 분기). 전제 데이터·평가 절차는 `eval_fill_v4i.load_clean()` 632셀과 v4j/v4k의 구성 단위 nested CV(외부 5-겹 / 내부 4-겹) 그대로.

## 0. 왜 앙상블인가 — v4k가 남긴 두 사실

1. **통합 모델은 소형 셀을 못 맞춘다** (R1-1). 추론 <10 ms 117셀의 MdAPE 90.1%, 학습 <1 s 166셀 MAPE 17.5%. 오버헤드 피처 추가(→168%)와 Huber(→120%)는 답이 아니었다. 그런데 **소형 셀만으로 학습한 전문 모델**은 같은 117셀에서 MAPE 22.6%, 학습 <1 s는 8.1%. 즉 정보는 피처에 있고, 통합 로그 목적함수가 소형 셀을 과소 가중하는 게 문제다.
2. **튜닝을 맞추면 XGB·GB·RF가 동률이다** (R1-8). 구성 단위 XGB 0.9906/0.9891, GB(grid) 0.9891/0.9904, RF(grid) 0.9852/0.9867. 서로 다른 귀납 편향의 모델이 같은 정확도면 평균으로 분산을 줄일 여지가 있다(기대 이득은 작다: R² 0.001~0.003).

3. **(구현 중 발견) 타깃 변환 자체가 소형 셀을 지운다.** 논문 모델의 타깃은 z = log1p(y), y는 **초** 단위다. 추론 셀은 0.0015~71 s, 학습 셀은 0.11~5290 s인데, log1p(y)는 y < 0.1에서 사실상 y와 같다(log1p(0.005)=0.00499, log1p(0.01)=0.00995). 즉 10 ms 미만 구간에서는 "로그 공간 제곱오차"가 **초 단위 제곱오차**로 퇴화한다. 5 ms 셀을 90% 틀리면 손실 기여 (0.0045)² ≈ 2×10⁻⁵, 10 s 셀을 14% 틀리면 (0.13)² ≈ 0.017 — 천 배 차이. 트리는 소형 셀을 맞출 이유가 없다. 같은 이유로 "R²(log)"도 소형 구간에서는 선형 R²다(R1-1의 지적이 정확히 이것). 전문 모델이 잘 되는 건 부분집합 안에서 스케일이 균일해 절대 오차 ≈ 상대 오차이기 때문이다. → **후보 F: 타깃을 log(y) 또는 log1p(y·1000 ms)로 바꾼 단일 XGB**. 한 줄 변경이고 앙상블보다 먼저 시험한다.

**주의 — v4k의 전문 모델 수치는 상한이다.** `overhead_features()`의 `specialist_small`은 `small = np.expm1(y) < 0.05`처럼 **실제 타깃으로 부분집합을 골랐다**(oracle gate). 배포 시에는 y를 모르므로 피처나 통합 모델의 예측으로 라우팅해야 하고, 그 게이트 오류가 22.6%를 얼마나 갉아먹는지가 이 설계의 핵심 질문이다.

## 1. 후보 세 가지와 선택

| 후보 | 구조 | 기대 효과 | 비용 | 판단 |
|---|---|---|---|---|
| A. 알고리즘 평균 | XGB·GB·RF 로그 예측의 평균 또는 Ridge 스태킹 | R² +0.001~0.003, 소형 구간엔 효과 없음 | 학습 3배 | 보조 층으로만 |
| **B. 구간 게이트 앙상블** | 통합 모델 + 소형 전문 모델 + 게이트 | <10 ms MAPE 148%→(게이트 정확도에 따라) 30~60% | 학습 2배 + 게이트 | **주 설계** |
| C. 백엔드별 전문가 | 백엔드마다 모델 4개, 통합과 평균 | v4k (c)행이 "라벨 1개 = 기술자 30개"를 보였으므로 통합 모델이 이미 백엔드별 모델과 같음 | 4배 | 기준선으로만 1회 측정 |
| **D. 가중 통합 모델** | 단일 XGB, `sample_weight`를 소형 셀에 크게(z가 작을수록 가중 ↑) | 진단("소형 셀 과소 가중")을 가장 싸게 직접 검증. 게이트·불연속·누수 위험 없음 | 학습 1배 | **B보다 먼저** |
| **E. 잔차 보정** | 통합 모델의 OOF 잔차를 두 번째 XGB가 학습, 소형 구간에서만 더함 | 게이트 없이 매끄러운 보정. 전문 모델을 "잔차 전문가"로 바꾼 B의 연속판 | 학습 2배 | B 직전 |
| **F. 타깃 변환** | 단일 XGB, 타깃을 log(y) 또는 log1p(y·1000)으로 | §0-3의 원인을 직접 제거. 모델 구조 변경 없음 | 학습 1배 | **맨 먼저** |

B를 주 설계로 하되, **F → D → E → B 순서로** 돌린다. 진단이 맞다면 D만으로도 소형 구간이 좋아져야 하고, D가 안 되는 걸 보인 뒤에야 게이트 앙상블의 복잡성이 정당화된다. A는 B의 각 구성원(통합·전문)에 선택적으로 얹는 층, C는 "앙상블이 백엔드 분리와 다르다"는 걸 보이기 위한 대조군이다.

## 2. 구간 게이트 앙상블 — 정의

타깃별(학습시간, 추론시간) 독립. 모든 계산은 로그 공간 `z = log1p(y)`.

```
fit(X_tr, z_tr):
    base       = nested-tuned XGB on all of (X_tr, z_tr)             # 지금의 통합 모델 그대로
    S          = { i : z_tr[i] < τ_s }                                # 학습 라벨로만 고른 소형 부분집합 (허용)
    specialist = XGB(depth 3, 200 trees) on (X_tr[S], z_tr[S])        # 셀 150~200개라 얕게
    gate       = 아래 셋 중 하나

predict(X):
    z_b = base.predict(X)
    z_s = specialist.predict(X)
    w   = gate(X, z_b)                     # ∈ [0, 1], 전문 모델 가중
    return (1 − w)·z_b + w·z_s
```

게이트 세 가지 (하이퍼파라미터로 두고 내부 CV로 고른다):

| 게이트 | w 정의 | 장점 | 단점 |
|---|---|---|---|
| `hard` | w = 1[z_b < τ] | 단순, 해석 쉬움 | τ 근처 불연속, base가 틀리면 그대로 틀림 |
| `soft` | w = σ((τ − z_b)/β) | 경계 매끈, β로 폭 조절 | β 추가 튜닝 |
| `clf` | w = P(소형 \| X), 로지스틱 또는 XGB 분류기, 라벨은 z_tr < τ_s | base 오류와 독립 | 분류기 자체의 오류; 피처만으로 구간을 맞힐 수 있는지가 관건 |

임계값: 추론 τ_s = log1p(0.05) (v4k 전문 모델과 동일, 50 ms), 라우팅 τ = log1p(0.02)~log1p(0.05) 그리드. 학습 τ_s = log1p(1.0), τ = log1p(0.5)~log1p(1.0). **τ_s > τ로 두어 전문 모델의 학습 범위가 라우팅 경계보다 넓게** — 경계 바로 위 셀이 전문 모델에 낯설지 않도록.

누수 방지 규칙 (v4k와 같은 nested CV 안에서):
- τ, β, 게이트 종류는 **내부 4-겹에서** 고른다. 외부 테스트 폴드의 y는 어디에도 쓰지 않는다.
- S는 외부 학습 폴드의 라벨로만 정한다. 예측 시 라우팅은 X와 z_b만 쓴다.
- 구성 단위 GroupKFold 유지(같은 구성의 4백엔드 셀은 같은 폴드).

## 3. 코드 구조

sklearn 호환 추정기로 만들어 v4j `nested_oof()`·v4k `Ctx._nested_models()`·`GridSearchCV`를 **수정 없이** 재사용한다.

```
benchmark/predictor/__init__.py
benchmark/predictor/ensemble.py      LogTargetXGBRegressor (F) · WeightedXGBRegressor (D) · ResidualCorrectedRegressor (E)
                                     RegimeEnsembleRegressor (B)(BaseEstimator, RegressorMixin)
                                       params: tau, tau_s, gate ∈ {hard, soft, clf}, beta,
                                               base_params, spec_params, average ∈ {none, xgb_gb_rf}
                                     AlgoAverageRegressor                    # 후보 A
                                     PerBackendRegressor                     # 후보 C (대조군)
eval_fill_v4l.py                     아래 §4의 절들, 산출 paper/v4_measured_l.json
make_tables_v4l.py                   paper/v4l_tables.md
predict_v4.py (신규)                 논문 파이프라인용 배포 스크립트: onnx_oplevel + merged_schema 120열
                                     → joblib 번들(base·specialist·gate·NUMERIC) 로드 → 예측
```

**배포 경로 주의.** 기존 `train_predictor.py`/`predict_from_onnx.py`는 **구판 45피처 파이프라인**이다 (`train_predictor.py:340`이 `FEATURE_COLUMNS` 45개를 저장, `predict_from_onnx.py:29`가 `onnx_extractor.extract_features_from_onnx` 구판 추출기 사용). 논문 모델은 `eval_fill_v4i.onnx_rows_of()` → `onnx_oplevel` + `merged_schema` 120열이고 **이 경로에는 배포 스크립트가 없다.** 앙상블과 무관하게 `predict_v4.py`가 필요하며, 앙상블 번들은 그 위에 얹는다. 구판 두 스크립트는 건드리지 않는다.

`benchmark/predictor/`에 두는 이유: joblib 역직렬화 시 클래스 경로가 import 가능해야 하고, 실험 스크립트(`eval_fill_*`)와 배포 경로가 같은 구현을 쓰게 하기 위해서다.

`RegimeEnsembleRegressor.fit()` 안에서 base의 그리드 탐색은 하지 않는다 — 바깥 `GridSearchCV`가 `{tau, gate, beta} × XGB_GRID`를 한 번에 돈다. 그리드가 커지므로(2×3×2 × 4 = 48) 내부 4-겹 기준 폴드당 192회 학습이다. v4k `overhead_features` 절이 102 s였으니 이 절은 약 15~20분으로 잡는다.

## 4. 평가 절 (eval_fill_v4l.py)

| 절 | 질문 | 산출 |
|---|---|---|
| `gate_analysis` | 피처만으로 소형 구간을 얼마나 가를 수 있나 | 분류기 AUC·정확도(구성 단위 CV); base 예측으로 라우팅했을 때 혼동행렬(진짜 소형 vs 예측 소형) |
| `regime_ensemble` | 게이트별·τ별 nested CV 성능 | R²(log), MAPE·MdAPE·±20%를 전체/≥10 ms/<10 ms/GAN으로. 기준선 = v4k `baseline_120`, 상한 = v4k `specialist_small`(oracle) |
| `algo_average` | XGB+GB+RF 평균·Ridge 스태킹이 base·specialist 각각에 주는 이득 | 같은 지표 |
| `per_backend_control` | 백엔드별 4모델이 통합과 다른가 | 같은 지표 (대조군) |
| `ladder_check` | 앙상블이 외삽(사다리 3~5단계: 폭·깊이·최대 사분위)에서 통합보다 나빠지지 않나 | 단계별 R²(log)·MAPE, 통합 대비 차이 |
| `seed_stability` | 최선 구성으로 시드 10개 | 평균 ± 표준편차 |

전부 구성 단위 nested CV. `Ctx.base()`의 통합 OOF를 그대로 기준선으로 쓴다.

**판정 기준** (사전에 고정):
- 채택: 추론 <10 ms MAPE 148.5% → **60% 이하**(MdAPE 40% 이하), 동시에 ≥10 ms MAPE 악화 1.0 pt 이내, 전체 R²(log) 변화 ±0.002 이내, 사다리 3~5단계 R²(log) 하락 0.005 이내.
- 기각: 위 중 하나라도 어기면 "게이트 오류가 전문 모델 이득을 상쇄한다"를 수치로 보고하고 통합 모델 유지.
- 학습시간 타깃은 <1 s MAPE 17.5% → 12% 이하를 같은 조건으로.

2단계가 관문이다. 소형 구간이 피처로 갈리지 않으면(AUC 낮음) `hard`/`soft` 게이트는 base 예측에 의존하는데, base가 소형 구간에서 MdAPE 90%로 틀리므로 라우팅도 틀린다. 그 경우 대안은 **경계 근처를 넓게 잡은 soft 게이트**(β 크게)뿐이고, 이득은 줄어든다.

## 6. 논문과의 관계

- RACS camera-ready(마감 10/7)에는 **넣지 않는 것을 기본**으로 한다. 8쪽 제한이 이미 빡빡하고, 앙상블은 "통합 모델 하나"라는 논문 틀을 바꾸는 일이라 camera-ready에서 할 변경이 아니다. v4k의 전문 모델 한 문장("소형 전문 모델로 19%까지 내려간다, 단 oracle 게이트")으로 충분하다.
- 앙상블이 판정 기준을 통과하면 다음 논문(국문 학술발표회 또는 저널 확장판)의 기여로 쓴다: "구간 게이트 앙상블이 소형 셀 오차를 통합 모델 대비 n배 줄이면서 R²·외삽 성능을 유지".
- 통과 못 해도 결과는 쓸모 있다: "정적 피처만으로는 실행 오버헤드 구간을 분리할 수 없다"는 한계를 게이트 AUC로 정량화한다.

| 위험 | 대응 |
|---|---|
| oracle 게이트(22.6%)와 학습 게이트의 격차가 큼 | 2단계에서 먼저 측정, soft 게이트로 완충 |

**결론: 앙상블은 필요 없다. 타깃 변환 한 줄(F)이 oracle 상한에 도달하고, 백엔드별 분리와 결합(F+C)하면 두 타깃 모두에서 최선이다.**

읽기.
- **F 하나로 추론 소형 MAPE 221.6→21.2, 전체 58.1→16.4, 대형 21.0→15.3.** R²(log)는 그대로(0.9899→0.9902). §0-3의 진단이 맞았다: 문제는 모델이 아니라 log1p(초) 타깃이었다. 시드 10개에서도 소형 22.1±5.0 (기준선 170.3±35.2), 대형 16.7±0.5 (22.4±1.0).
- D·E·A는 log1p(초) 공간에 남아 있어 같은 결함을 물려받는다. E는 잔차 모델이 거의 켜지지 않았고, A의 평균은 소형 구간을 못 고친다.
- B는 게이트가 잘 갈리는데도(AUC 0.998) F에 못 미친다(clf 24.3, hard 30.7). **자동 선택은 soft(45.4)를 골랐다** — 내부 CV의 선택 지표가 R² in log1p이라 소형 구간에 유리한 게이트를 못 고른다. 선택 지표 자체가 같은 결함을 갖는다.
- **C(백엔드별 분리)는 학습시간에서 통합보다 낫다**(전체 14.3 vs 17.3, 소형 8.6 vs 17.5). v4k (c)행("라벨 1개 = 기술자 30개")은 R²(log) 기준이었고, MAPE로 보면 분리가 이긴다. F+C가 두 타깃 모두 최선이며 추론 소형 19.0은 oracle 상한과 같다.
- 외삽(사다리 3~5단계): F는 기준선 대비 R²(log) −0.006~−0.001로 판정 기준(0.005) 경계에 있으나 MAPE는 절반 이하(추론 L3 110→54, L4 71→28, L5 275→155). D는 L5에서 나빠짐(0.882→0.869).
- 기준선 소형 MAPE가 기기·시드에 크게 흔들린다(데스크톱 v4k 148.5, 맥 221.6, 시드 10개 170±35). 2~10 ms 셀에서 트리 분기 몇 개가 뒤집히면 상대 오차가 100%p 움직인다. 비교는 같은 기기·같은 시드 안에서만.

**판정.** §4 기준(추론 소형 MAPE 60% 이하, 대형 악화 1 pt 이내, R² ±0.002, 외삽 하락 0.005 이내): F는 외삽 R² 한 항목이 −0.006으로 경계, 나머지 전부 통과. F+C는 R²·MAPE 전부 통과(외삽은 미측정 — 후속). B는 소형 기준은 통과하나 F에 지므로 채택 이유가 없다.

**논문에 주는 의미.**
1. R1-1(R² 0.99 vs MAPE 54%)의 답이 바뀐다. "소형 전문 모델로 19%"(oracle, 배포 불가)가 아니라 **"타깃을 log(y)로 바꾸면 단일 모델로 16%"**(배포 가능, 구조 변경 없음). 이건 camera-ready에 넣을 수 있는 크기의 수정이다 — §3.4 한 문장 + §4.1 표 5·오차표 수치 교체.
2. 다만 R²(log) 지표 정의(log1p 공간)는 논문 전체에 걸쳐 있으니 지표는 그대로 두고 **학습 타깃만** 바꾸는 것이 안전하다. 두 값은 같은 공간에서 비교 가능(F의 R²(log)는 log1p 공간에서 계산했다).
3. C의 학습시간 우위는 기여 1("통합 모델")과 긴장 관계다. F+C를 본문에 넣으면 "unified"를 다시 정의해야 한다. camera-ready에서는 F만 넣고 F+C는 후속 논문으로 두는 것을 권한다.

**후속(미실행).** F+C의 사다리·시드, F 채택 시 v4k 전 절(중요도·절제·라벨 vs 기술자) 재계산, `predict_v4.py` 번들을 F+C로.

### 9.1 기여 2 재검증 — log(y) 타깃에서도 mem_write > FLOPs가 유지되는가 (`log_target_claims`, `paper/v4l_claims.log`)

같은 기기·같은 절차(통합 XGB 구성 단위 nested CV, 폴드별 홀드아웃 permutation 20회, gain 순위, 대칭 절제)로 log1p와 log을 나란히 돌렸다.

| 타깃 | 변환 | Δperm mem_write | Δperm flops | Δperm MEM(3) | Δperm FLOPs(14) | Δperm 계열ID | gain 순위 mem_write | −MEM R² / MAPE | −FLOPs R² / MAPE |
|---|---|---:|---:|---:|---:|---:|---|---:|---:|
| 학습 | log1p | 0.543 | 0.014 | 0.598 | 0.193 | 0.021 | 1,1,1,1,1 | −0.004 / 17.3→20.5 | +0.000 / →18.2 |
| 학습 | **log** | 0.584 | 0.011 | 0.670 | 0.136 | 0.011 | 1,1,1,1,1 | −0.005 / 15.9→19.7 | +0.000 / →16.8 |
| 추론 | log1p | 0.864 | 0.024 | 0.909 | 0.051 | 0.006 | 1,1,1,1,1 | −0.006 / 58.1→51.1 | +0.001 / →61.6 |
| 추론 | **log** | 0.723 | 0.011 | 0.891 | 0.030 | **0.324** | **2,2,2,2,2** | −0.007 / 16.4→20.9 | +0.001 / →16.6 |

**유지되는 것.** mem_write ≫ FLOPs는 두 타깃·두 변환 모두에서 그대로다(permutation 0.58/0.72 vs 0.01, 절제 −MEM만 MAPE를 3~4 pt 올림). 기여 2의 문장("가장 일관된 단일 기술자, 고유 정보 아님")은 log(y)에서도 성립한다.

**바뀌는 것.** 추론 타깃에서 **계열 식별자(`model_family_encoded`)가 gain 1위로 올라오고 mem_write는 5폴드 모두 2위**, permutation 하락도 0.006→0.324. 이유는 명확하다: log(y)가 소형 셀(대부분 ANN)을 손실에 되살리면서, 그 구간을 맞히는 데 "이 셀이 ANN이다"라는 정보가 필요해진 것이다. log1p에서는 소형 셀이 손실에 없었으니 계열 정보도 필요 없었다.

**논문에 주는 의미.** (1) §4.3의 "mem_write가 전 폴드 1위"는 학습시간에만 참이 되고, 추론은 "계열 식별자 다음 2위"로 써야 한다. 기여 2 자체는 살아남는다. (2) 계열 식별자 의존이 커지면 LOFO(사다리 6단계, 계열 외삽)가 더 나빠질 수 있다 — 채택 시 사다리 6·7단계도 재계산해 확인해야 한다(미실행). (3) 이건 log(y)의 결함이 아니라 정직한 결과다: 소형 셀을 실제로 예측하려면 계열 정보가 필요하다는 뜻이고, log1p 모델은 그 셀들을 예측하지 않았기 때문에 그 의존이 안 보였을 뿐이다.
