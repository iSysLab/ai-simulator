# 외부 백엔드 결과 — GTX 1050 (2026-09-19)

측정: 브랜치 `external-gtx1050`(d6476a0), 런북 `72_external_backend_runbook.md` §3. 분석: `eval_external_backend.py`, 수치 `paper/external_gtx1050.json`(기술자 갱신)·`paper/external_gtx1050_norefresh.json`(라벨만).

## 1. 기기와 측정

| 항목 | 값 |

| 유휴 | Windows Search 인덱서가 CPU 15~25% 상시 점유 → `--idle-cpu-max 35`로 진행, `load_cpu_pct` 0.4~33.2 기록. 대기 5행 |
| 계열 | ANN 10 · CNN 8 · ResNet 10 · MobileNet 10 · ViT 9 · GAN 8 |

**4060 Ti 대비 실측 비(같은 구성, 중앙값)**: 학습 2.94× (1 s 미만 1.84×, 10 s 이상 7.22×), 추론 3.51× (1.23×, 4.47×). TFLOPS 비 10.7×와 비교하면 소형 모델은 커널 실행 오버헤드(launch-bound)에 묶여 GPU 성능 차이가 거의 안 드러나고, 대형만 계산 비율에 가까워진다.

| 예측기 | 학습시간 | 추론시간 |

## 3. 읽기 (§3.1의 의존도 분석으로 정정)

1. **갱신 모델이 "4060 Ti 실측 복사"를 두 타깃 모두 이긴다**(R² 0.61/0.78 vs −0.11/0.09, MAPE 54/42 vs 70/68). 4060 Ti 값을 그대로 쓰면 3.3~3.6배 빠르게 예측하는데(0.30), 갱신 모델은 그 격차의 절반쯤을 메운다(0.41, 0.59). 순위는 잘 보존된다(Spearman 0.97). **그러나 이것은 사양을 이해해서가 아니다** — §3.1 참조.
2. **절대 수준은 못 맞춘다.** 여전히 실측보다 1.7~2.4배 빠르게 예측한다. "4백엔드 평균"이라는 무학습 기준선이 MAPE에서 더 낫다(32/49) — GTX 1050의 속도가 우연히 네 백엔드 가운데쯤이라서이지 방법이 아니다.

### 3.1 입력 피처 의존도 재분석 — "반쯤 맞힌" 것은 VRAM 분기 하나였다 (`paper/feature_dependence_log.json`)

GTX 1050 사양 16개(코어 640, TFLOPS 2.51, 클럭 1.96, VRAM 2, CPU 4코어, RAM 7.8 …)를 하나씩 4060 Ti 값으로 되돌리며 예측 변화를 쟀다.

| 되돌린 기술자 | 학습 pred/true | 추론 pred/true |
|---|---:|---:|
| (GTX 값 그대로) | 0.41 | 0.59 |
| **`dedicated_vram_gb` 2→8** | **0.29** | **0.27** |
| `tflops_fp32` 2.51→26.98 | 0.41 | 0.59 |
| `gpu_cores` 640→4352 | 0.41 | 0.59 |
| `gpu_clock_ghz`, `cpu_cores`, `ram_total_gb`, 나머지 12개 | 0.41 | 0.59 |
| 전부 4060 Ti 값 | 0.29 | 0.27 |

**VRAM 하나만 예측을 움직이고 나머지 15개는 변화 0.** SHAP(pred_contribs)로 GTX 행과 같은 구성의 4060 Ti 행의 예측 차이를 분해해도 학습 +0.491 중 `dedicated_vram_gb` +0.466, 추론 +0.737 중 +0.747 — 사실상 전부다. 실제 차이는 log(2.9~3.5) ≈ +1.1~1.25이므로 VRAM 분기가 만든 이동은 필요량의 40~60%다.

왜 그런가. 632셀에서 `dedicated_vram_gb`는 CUDA 8·나머지 0이라 트리가 "8 미만이면 CUDA 아님" 분기 하나로 백엔드를 갈랐고, GTX의 2 GB가 그 분기의 "CUDA 아님" 쪽으로 떨어져 MPS/CPU 쪽 잎으로 밀린 것이다. TFLOPS·코어·클럭은 학습 데이터에서 백엔드와 완전히 공선이라 트리가 한 번도 분기에 쓰지 않았다.

log(y) 모델 전체의 의존도(구성 단위 5폴드, gain 합 / 그룹 permutation ΔR²(log)):

| 피처 그룹 (열 수) | 학습 gain | 학습 Δperm | 추론 gain | 추론 Δperm |
|---|---:|---:|---:|---:|
| op-level·FLOPs·메모리 (18) | 0.766 | 1.364 | 0.057 | 1.043 |
| 계열 식별자 (1) | 0.122 | 0.012 | 0.932 | 0.363 |
| 구조 (62) | 0.059 | 0.032 | 0.004 | 0.035 |
| 하드웨어 (30) | 0.053 | 0.519 | 0.007 | 0.704 |
| 입력 (9) | 0.000 | 0.000 | 0.000 | 0.000 |

하드웨어 30열은 gain으로는 5%/0.7%인데 permutation으로는 0.52/0.70 — 분기는 몇 개 안 쓰지만(`gpu_count` 0/1, `dedicated_vram_gb` 0/8) 그 몇 개가 백엔드 정체성을 통째로 나른다. 즉 **모델은 하드웨어를 "어느 기기인가"로만 쓰고 "얼마나 빠른 기기인가"로는 쓰지 않는다.** v4k (c)행("라벨 1개 = 기술자 30개")의 기계적 이유가 이것이다.

**따라서 §3-1의 "이긴다"는 사양 학습의 증거가 아니라 VRAM 임계값의 우연이다.** 새 GPU의 VRAM이 8 GB 이상이었다면(예: 3060 12 GB) 4060 Ti 쪽 잎으로 떨어져 "복사"와 같은 예측이 나왔을 것이다. R1-5 반례로 쓸 수 없다.
3. **라벨만 주면 반대 방향으로 틀린다.** VRAM 2 GB만 실제값으로 두면 모델이 8·18·0 어느 쪽에도 없는 값을 CPU 쪽으로 분기시켜 1.6~2.2배 느리게 예측한다. 기술자 한 개만 바꾸는 것은 위험하고, 전부 함께 갱신해야 한다.
4. **TFLOPS 비례 스케일링은 최악.** 소형 모델은 launch-bound라 3배도 안 느린데 10.7배를 곱한다. Roofline 서술(§4.3)의 실측 근거: 실행시간은 계산량 비가 아니라 메모리·오버헤드 체제에 따라 갈린다.
5. MPS 시뮬레이션(0.73→−0.40)과 달리 여기서는 갱신이 도움이 됐다. 차이: GTX 1050은 4060 Ti와 **같은 장치 종류·같은 소프트웨어 스택**이라 기술자가 "CUDA 안에서 어디쯤"만 알려주면 되지만, MPS는 CUDA와 스택이 달라 기술자로 잇기 어렵다.

### 3.2 새 기기를 학습에 포함하면 — 몇 개 구성이면 되나 (`paper/external_gtx1050_fewshot.json`)

"0개로는 안 된다"가 §3.1의 결론이면, 실용적인 다음 질문은 "새 기기에서 몇 개만 재서 넣으면 되나"다. GTX 1050의 55구성 중 k개(계열별 균등)를 632셀에 더해 학습하고 나머지 1050 구성으로 평가했다(log(y) 타깃, 시드 5개 평균).

| 1050 구성 학습 포함 | 학습 MAPE / MdAPE / pred÷true | 추론 MAPE / MdAPE / pred÷true |
|---|---|---|
| 0개 (= §2의 갱신 모델) | 54.0 / 59.0 / 0.41 | 42.0 / 41.6 / 0.59 |
| **6개 (계열당 1개)** | 39.3 / 29.9 / **0.98** | 26.7 / 19.2 / **0.96** |
| 12개 | 23.8 / 21.2 / 0.95 | 23.5 / 19.1 / 0.88 |
| **24개 (계열당 4개)** | **19.3 / 15.2 / 0.93** | **17.6 / 12.9 / 0.95** |
| 36개 | 15.9 / 13.7 / 0.99 | 22.2 / 14.2 / 0.99 |
| (참고) 4백엔드 in-distribution | 15.9 / 12.3 | 16.4 / 12.1 |

읽기.
- **계열당 1개(6구성)만 넣어도 2배 낙관 편향이 사라진다**(0.41→0.98, 0.59→0.96). 새 기기의 "높이"는 몇 점만 있으면 잡힌다.
- **계열당 4개(24구성, 3회 반복이면 저사양 GPU에서 약 30분)면 기존 4백엔드와 같은 정확도**(MAPE 18~19% vs 16%)에 도달한다.
- 36개에서 추론이 소폭 나빠지는 건 남은 평가 셀이 18개뿐이라 잡음(±6.9).
- 기제는 §3.1과 같다 — 모델이 사양을 배운 게 아니라 "VRAM 2 GB인 기기"라는 새 정체성의 잎을 몇 점으로 채운 것이다. 그래서 이 결과는 "미지 기기 예측"이 아니라 **"기기 추가 비용"**으로 읽어야 한다: 새 플랫폼을 시스템에 넣는 데 필요한 측정이 160구성 × 10회가 아니라 24구성 × 3회다.

## 4. 논문에 주는 것

- R1-5·R2 답변에 한 문장: "5번째 기기(GTX 1050)에서 4백엔드 모델은 절대 수준을 1.7~2.4배 낙관적으로 예측했고, 사양 기술자 중 예측을 움직인 것은 VRAM 분기 하나뿐이었다 — 기기당 사양 값이 하나뿐인 데이터에서 트리는 하드웨어를 정체성으로만 쓴다(§3.1)." 리뷰어 지적을 실측으로 확인한 것이지 반례가 아니다.
- camera-ready(10/7)에는 Limitations 한 문장 또는 §4.4 한 행. 표까지는 분량상 어렵다.
- 후속: 기술자 축을 채우려면 GPU 2~3대가 더 필요하다(예: 3060, 1660, T4). 그때는 `tflops`·`gpu_cores`가 연속 축이 되어 트리가 보간할 수 있다.
